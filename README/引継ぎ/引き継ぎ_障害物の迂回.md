# 引き継ぎ: 障害物が密集しても歩行者が詰まらないようにする

## 対応済み（2026-10-12）
下の方針案 2（`AStarGrid2D` の格子 A\*）で置き換えた。ナビメッシュは、ベイクやマップ同期のタイミングがヘッドレスのテストで扱いにくいため見送った。
- [Geometry.gd](../script/utils/Geometry.gd)
  - `make_grid()`: 障害物を `body_radius` だけ太らせて格子に塗る（格子の間隔も `body_radius`）。
  - `find_path()`: A\* で経路を探し、見通せる区間の点を飛ばして曲がり角だけにする。ゴールが囲まれているときは、たどり着ける一番近い点で止める。
  - `farthest_visible()`: 経路のうち、今の位置から見通せる一番先の点を返す。
- `Steering.steer()`: ゴールが直接見えればそこへ向かう。見えなければ経路をたどる。経路は 1 秒ごとに引き直す。
- ランダムに歩く人の目的地は、たどり着ける点から選ぶ（`_reachable()`）。
- 迷路のシナリオ（互い違いの壁、列を囲むコの字、袋小路、60 人、30 秒）での結果:
  - 1 m 以内に止まり続けた時間の最大は 1.55 秒。前の方式では 27 人が詰まった。
  - 1 フレームの処理時間は 5.3 ms（前の方式は 4.5 ms）。
- 残っている制限:
  - 確実に通れるすき間は `3 * body_radius` 以上。
  - 出現位置が閉じた囲いの中だと、そこから出られない。
  - 列の延長線（最後尾より後ろ）が障害物の中にあると、合流する人はその手前で待つ。

以下は置き換える前の記録。

## 次にやること（済）
歩行者が障害物を避けるロジックを、ナビメッシュ（Godot の経路探索）に置き換える。今の方法では、障害物を迷路のように密集させると詰まる。

## 置き換える前の仕組み
- 迂回は [script/utils/Geometry.gd](../script/utils/Geometry.gd) の `next_waypoint()` が担当している（`ponytail:` コメントのある関数）。
  - 目的地への直線をふさぐ障害物のうち、一番手前の1つだけを見る。
  - その障害物の角（`margin` だけ外側）の中から、見通しが通って合計距離が最短の角を経由点にする。
  - 毎フレーム計算し直す。状態は持たない。
- 呼び出し元は [script/walk/Steering.gd](../../script/walk/Steering.gd) の `steer()` だけ。
  - `margin = body_radius * 3.0` で呼ぶ。
  - 戻り値の経由点へ向かう速度に、歩行者同士の回避力を足して動かす。
- めり込みは `Steering.resolve_all_overlaps()` の最後で、`Geometry.push_out_of_rects()` を使って押し出している。
- 障害物のデータ:
  - `obstacle_rects: Array[Rect2]` に、XZ 平面の床面の矩形として入っている。
  - 3D の箱（StaticBody3D と BoxMesh、高さは `obstacle_height`）は `_spawn_obstacles()` が作る。
  - 元データは `./.config/general.toml` の `[scene] obstacles`（描画画面の座標）。
- 動くのは自由歩行者だけ。具体的には、最後尾へ向かう人（`State.TO_LINE`）とランダムに歩く人（`State.TO_TARGET`）。
- 列に並んでいる人（`ON_LINE`）は線の上を進むだけで、障害物は見ない。線が障害物を貫通していても、それは描いた人の責任としている。

## 詰まるケース
- 障害物が複数並んでいて、1つ目の角を回っても次の障害物にふさがれるとき（コの字や迷路状）。
- 角の経由点が別の障害物の中や、障害物同士のすき間に入るとき。
- 目的地（列の最後尾）が障害物で囲まれているとき。

## 方針案（推奨順）
1. **NavigationServer3D で実行時にベイクして、`map_get_path()` で経路をとる**
   - 床（出現範囲 `spawn_half_x` × `spawn_half_z`）から障害物の矩形をくり抜き、`NavigationMeshSourceGeometryData3D` に入れてベイクする。または `NavigationPolygon` などで 2D 的に作る。
   - `agent_radius` は `body_radius` に合わせる。
   - 歩行者ごとに経路を持たせ、次の角へ向かう。`Steering.steer()` の経由点の計算をこれに差し替える。
   - 目的地が変わったときと、一定間隔で再計算する。
   - `simulation.tscn` に空の `Plane/NavigationRegion3D` がすでにあるので、それを使ってもよい。
   - API 名は推測で書かず、`.claude/skills/godot/scripts/docs/api_lookup.py` で確認する。特に、マップの同期タイミング（`map_force_update` の有無など）。
2. **2D グリッドの A\***
   - 障害物の矩形をグリッドに塗り、`AStarGrid2D` で探索する。
   - 依存はないが、経路がカクつくので平滑化が必要。
3. **いまの貪欲法を改良する**
   - 経由点も同じ手順で再帰的にたどる、など。
   - 安上がりだが、迷路状の配置は解けない。

`script/PedestrianAgent.gd` は過去の試作（NavigationAgent3D 版、未使用）なので、参考程度に見る。
