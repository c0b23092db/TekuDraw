# 引き継ぎ: リアルな3D描写

## 次にやること
シミュレーション画面（`scene/simulation.tscn`）の見た目を、物体追跡のデータセットに使えるくらいリアルにする（SPEC.md の残り機能「リアルな3D環境描写」）。

範囲はまだ決まっていない。始める前にユーザーと決めること:
- 人のモデルとアニメーション（歩く・止まる）
- 床、障害物、周りの環境（空、建物など）
- 光と影、時間帯、天気
- 出力: 画面を見るだけか、動画や連番画像として書き出すか

## 壊してはいけないこと
### 1. 同じシードなら同じ動き（リプレイの前提）
- 動きの計算は [SimulationManager3D.gd](../script/SimulationManager3D.gd) の `_physics_process`（固定の刻み 1/60 秒）だけで進める。`_process` や描画のフレームレートに依存させない。
- 乱数は `rng`（シードで初期化した `RandomNumberGenerator`）からだけ取る。
- 見た目だけのランダム（服の色やモデルの選択など）を `rng` から取ると、動きの乱数の順番がずれてリプレイが変わる。
  - 見た目用には別の `RandomNumberGenerator` を作る。シードは `rng.seed` から作る（例: `rng.seed + 1`）。リプレイで見た目も同じになる。
  - グローバルの `randf()` / `randi()` は使わない。
- 確認: `test/test_determinism.gd`（後述）が OK のままであること。

### 2. 見た目と当たり判定を一致させる
- 人の当たり判定は半径 `w.radius`（`body_radius` × 人ごとの大きさのばらつき）の円。
- 見た目は `w.node.scale` を同じ割合で変えている（`_respawn()`）。新しいモデルも `w.node` の子に入れ、この scale に従わせる。
- モデルの向きは `_face()` が `w.node.rotation.y` を変える。モデルの正面がずれるときは、設定の `model_yaw_offset_deg` で直せる。
- 障害物の見た目（`_spawn_obstacles()` の箱）は、`obstacle_rects` と同じ位置・大きさに保つ。

### 3. データセットに映ってはいけないもの
- 列の線（`_draw_3d_line()` の赤い線）と `CameraController` の操作説明・時刻の表示はデバッグ用。シミュレーション中に Space で両方消える。

## 気をつけること
- **大きさの単位**: 3D の長さは m、速さは m/秒。設定ファイルも同じ単位で書く。
  - 描画画面の 1px は `Geometry.PX`（0.025 m）。画面全体（1280×720）が 32 m × 18 m になる。
  - 2026-10-13 までは 1px = 0.1 で、値は今の 4 倍だった。`.config` は 4 で割って書き直した（シード・優先度・時間・割合は変えていない）。
  - それより前に作ったリプレイ（`.config/replay/`）は古い単位なので、同じ動きにならない。
- **アニメーション**: 歩きの速さは `w.velocity` の長さで分かる。止まっている理由（譲る、待つ、列が止まっている）でアニメーションを変えたいときは、状態（`w.state`、`crossing.line_must_yield()`、`crossing.crosser_speed()`）を見る。
- **重さ**: 人数は動物体ごとに最大 500 人。重いモデルを使うときは、LOD やインスタンシングを考える。今の処理時間は、障害物 11 個・60 人で約 5 ms/フレーム（見た目を除く）。
- **画像の書き出し**: Godot の Movie Maker モード（`--write-movie`）を使うと、固定の fps で1フレームずつ書き出せる。物理の刻みとの対応（1フレーム = 1刻みになるか）は未確認。
- **正解データ**: [DatasetExporter.gd](../script/DatasetExporter.gd) は時刻を `Time.get_ticks_msec()` で記録している。これは実行のたびに変わる。リプレイと突き合わせるなら刻みの番号にする。

## ここまでにできていること
- 障害物の迂回（格子の A\*）: [引き継ぎ_障害物の迂回.md](引き継ぎ_障害物の迂回.md)
- 道を譲る・列を横切るの優先度（人ごと）。待てる時間を超えたら横切る。
- 動物体ごとの設定: 速さ・大きさ・列の左右のぶれのばらつき、出現の間隔。
- 乱数のシードと固定の刻み。
- リプレイ:
  - シミュレートするたびに `./.config/replay/日時_seed番号.toml` に保存する（シード、コミット、物理の刻み、全設定、動物体、障害物）。`.gitignore` 済み。
  - 描画画面の「リプレイ」ボタンでファイルを選んで再生する。
  - 記録したときとコードが違うと警告を出す。未コミットの変更があるときも出す。
- 障害物の撤去: 「設置：障害物」モードで右クリック（画面に案内を表示）。
- 列への並び方と横切り（2026-10-13）:
  - 最後尾の後ろ 1 m（`JOIN_RADIUS`）まで来たら列に入り、ずれは歩いて詰める。並びに行く人は列の速さの 1.3 倍（`CATCH_UP`）以上で歩く。
  - 並びに行く人も、列を横切るときはランダムに歩く人と同じ決まり（優先度・待てる時間）に従う。
  - 列に並んでいない人は、列の人を「よける」対象にしない（列とのやりとりは横切りの決まりだけ）。
  - 「列の人が道を譲る距離」は体どうしのすき間で測る。待ち始めた人は、列のそばにいる間 `waited` を数え続ける。
  - 試してだめだったこと: 並びに行く人に順番を付けて並ばせる（列が空になると全員の位置が一斉に変わる）。横から近づく人にも列の人が止まる（前を歩く人まで止まり、すき間ができず列が詰まる）。
  - 列の人は先頭から順に動かし、前の人の gap より近づかない（前の人が道を譲って止まっても通り抜けない）。
  - 列の人の進む向きは中心線の向き（`Crossing.line_dir()`）。自分の位置から中心線の先の点へ向けると、左右にずれた人ほど横を向く。
  - 横切る人は、先を譲る列の人が近づくと、すき間 1.5 m から遅くなり 0.5 m で止まる。列の人の通り道の中にいたら止まらずに渡りきる。待つ間は向きを変えない。
  - 列に並んでいない人は、列の人とのすき間が 0.3 m（`Steering.LINE_CONTACT`）より狭いときだけ列の人をよける。
  - 列に入れるのは最後尾より後ろにいるときだけ。
  - 試してだめだったこと（2026-10-14）: 通り道にいる人のためにも列の人が止まる（横切る人が集まると列が止まり、すき間が詰まって誰も抜けられない）。列の人をまったくよけない（止まった列の人に真正面からぶつかったまま動けない）。
  - `test/test_crowd.gd`: S 字の列で、並ぶまでの時間、ウロウロの回数、列の人どうしの重なり、止まったままの時間を測る。

## 2026-10-17 の変更
- 設定ファイルの読み書きを `ConfigFile` から [TomlFile.gd](../script/core/TomlFile.gd) に替えた。読むのは addons/toml（Godot TOML）の `TOML.parse_string`、書くのは自前（`[section]` と `key = 値` だけ）。読めないファイルは `*.broken` に残してから上書きする。
- 描画画面:
  - 右ドラッグで出現する場所の線（`spawn_points`、破線）を引く。「列削除」「出現削除」で選んでいる動物体の線を消す。
  - 左のパネルの VBoxContainer は全面のアンカー。縦に伸ばすと ItemList が伸びる。
- 列:
  - 列が空のとき、並びに行く人は線の一番近い所から入る（`_update_joiner`）。動物体の「空いた列には近い所から入る」（`join_nearest`、既定オン）を外すと、前の動き（始点まで行って並ぶ）。
  - ランダムに歩く人の目的地と現れる所は、列の線から `lateral_jitter + LINE_CLEAR` 以上離す（`_random_point`）。
  - 二本の経路（全体の設定 `two_routes`）: 列の人の間を通り抜ける道（距離 + 列ごとの `cross_cost`）と、列の端（最後尾の後ろは `spacing_max` ぶん余計に離す。並びに行く人とぶつからないように）を回り込む道を 1 秒ごとに比べる（`Routes.route()`）。乗り換えは `ROUND_MARGIN` 以上安くなるときだけ。
  - 「通り抜ける」は、人がいる区間の中心線から列の幅（`lateral_jitter + body_radius`）より近くを通ること。交わるかだけで見ると、列の端から中心線に沿って列の中を進む道を見逃す。
- 素材: `human_model_dir` が `res://` でなければ、FBX を実行中に `FBXDocument` で読む（取り込み不要。1ファイル約 1.5 秒）。設定画面でファイル・フォルダを選ぶと、アプリのフォルダの中なら `./` からの相対パスにする。
- `test/test_crowd.gd` はシードによって落ちることがある（2026-10-17 に 10 シードで計測。二本の経路なし 2/10、あり 3/10）。原因は列の手前で向かい合った横切る人どうしの詰まりなど、元からあるもの。

## 環境の注意
- Godot は `godot` で PATH が通っている（実体は上のフォルダの `godot.exe`）。出力を見るなら console 版を使い、`--headless` のときは `< /dev/null` を付ける。
- 見た目の確認は、ヘッドレスでない Godot で `scene/simulation.tscn` を読み込み、`root.get_texture().get_image().save_png()` で画像にすれば Claude も見られる（`.config` は読むだけで書き換えない）。
- Python は上のパスの実体を `-X utf8` 付きで使う（`python` はスタブ）。
- jj は winget 版。新しいシェルなら `jj` で動く。jj は `.gitattributes` の改行の設定を見ないので、CRLF のファイルが変更ありと出る（`working-copy.eol-conversion` は未設定）。
- godot-mcp-toolkit（MCP サーバー）は 2026-10-12 のセッションでは接続できなかった。
- `.tscn` を dispatcher の `scene_batch` で保存すると `uid=` が消える。小さな変更は手で編集する。
- 使わなくなったファイルは削除せず `trash/` に移す。
